## 0. 本書について

### 0.1 位置づけ（リバースエンジニアリング）
詳細設計書と同じく、本書も**先に作った実装を読み解いて**書き起こしたものである。<br>
私に実装の経験がないため、AIと対話しながら実装を進め、完成したソースから逆算して記録した。

| 状態 | 内容 |
|------|------|
| 単体テスト（3 章） | **実装済み**。3 章のケースをすべて自動テストにし、すべて成功（107 件）。push のたびに GitHub Actions で実行する |
| ビルドの確認（4 章） | 手動と GitHub Actions で確認する |
| 画面の確認（5 章） | 手動で確認する（リリース前に実施） |

### 0.2 用語
| 用語 | 意味 |
|------|------|
| 単体テスト | 関数や部品を 1 つずつ取り出し、「この入力ならこの結果になる」をプログラムで自動的に確かめるテスト |
| モック | テストのときだけ使う偽物。例: 本物の Qiita にアクセスするかわりに、決まった記事を返す偽の通信を使う |
| Vitest | 単体テストを実行する道具。このサイトで使っている Vite と設定を共有できる |
| Testing Library | 画面の部品を、テストの中で表示して確かめる道具 |
| CI | GitHub Actions のように、push のたびに自動でビルドやテストを実行する仕組み |

## 1. 方針

| 種類 | 対象 | 方法 | 実施のタイミング |
|------|------|------|----------------|
| 単体テスト | ロジック（P-01〜P-03、P-05〜P-10） | Vitest で自動実行 | push・毎朝のビルドのたびに GitHub Actions で実行 |
| ビルドの確認 | ビルド・デプロイ（P-04） | 手動 / GitHub Actions の結果を確認 | 初回公開時、`deploy.yml` を変えたとき |
| 画面の確認 | 見た目・アニメーション・画面遷移・レスポンシブ | ブラウザで目視 | リリース前、見た目を変えたとき |

- **ロジックは単体テストで守る**: 階数・URL・日付・サニタイズなどは、壊れても画面では気づきにくい。自動テストで毎回確かめる効果が大きい
- **見た目は画面の確認で守る**: 見た目やアニメーションは自動テストの手間が大きいため、チェックリストで最低限を確かめる
- **外部サービスにはアクセスしない**: 単体テストでは通信（`fetch`）をモックにし、Qiita・はてなブログの状態に左右されないようにする

### 1.1 単体テストの実行環境
| 項目 | 内容 |
|------|------|
